# Domaine Keycloak « gimac »

`gimac-realm.json` est produit par `generer-realm-gimac.py` à partir du realm de développement généré par JHipster ; ne pas l'éditer à la main, relancer le script.

Contenu : permissions (`HOM_*`, `CER_*`, `PAR_*`, `INTERNAL_*`) ; quatorze profils composites **par fonction** (D-58) : `ROLE_INGENIEUR_HOMOLOGATION`, `ROLE_CHEF_DES`, `ROLE_RSSI`, `ROLE_CONFORMITE`, `ROLE_DG`, `ROLE_CORRESPONDANT`, `ROLE_CHARGE_DDRM`, `ROLE_CHEF_DDRM`, `ROLE_SNA`, `ROLE_PRODUCTION_MONETIQUE`, `ROLE_POLE_RESEAU`, `ROLE_POLE_SYSTEME`, et le rôle dédié `ROLE_CONDUCTEUR_PROJET` (habilite à conduire tout projet ; le projet lui est confié par désignation) ; quinze utilisateurs de test (`test-*`, les correspondants portant `institution_id`) ; clients `tester-cli`, `homologation-service`, `certification-service`, `participant-service` ; claim `institution_id` dans le jeton.

**Double facteur (D-61).** Flux navigateur `navigateur-gimac` à niveaux d'assurance : niveau 1 mot de passe, niveau 2 mot de passe puis code TOTP (enrôlé à la première connexion, action `CONFIGURE_TOTP`). Les clients `web_app` (connexion par la passerelle) et `tester-cli` exigent le niveau 2 (`minimum.acr.value`) ; Keycloak pose le niveau atteint dans le claim `acr`, contrôlé par OPA à la passerelle et par chaque service. `tester-cli` accepte l'autorisation par appareil (RFC 8628) pour les contrôles cURL. Import vérifié le 29/09/2026 sur Keycloak 26.7.4 (distribution officielle) : domaine, flux, profil utilisateur, thème et comptes de service chargés sans erreur.

**Administration depuis la plateforme (D-62).** Permissions `IAM_*` et `PLATFORM_*` ; profil `ROLE_SUPER_ADMIN` (toutes les permissions d'administration, `ROLE_ADMIN` technique) et profil `ROLE_RSSI` étendu (administration des comptes sauf l'attribution d'un profil privilégié, politique de sécurité, messagerie, supervision en lecture) ; utilisateur de test `test-super-admin`. Client `iam-service` dont le compte de service porte les rôles `realm-management` utiles à MS-IAM (`manage-users`, `view-users`, `query-users`, `query-groups`, `manage-realm`, `view-realm`) ; client `gateway-supervision` (`ROLE_ADMIN`, lecture des points `/management`). Profil utilisateur déclaratif : attributs `institution_id`, `phone_number`, `fonction`, `profil_complet`, `langKey`, `login` modifiables par l'administration seulement (`unmanagedAttributePolicy: ADMIN_EDIT`), l'utilisateur les renseigne par « Mon compte ». Inscription libre fermée, mot de passe oublié réinitialisable, langues fr, en, es ; messagerie de développement vers Mailpit (`messagerie:1025`), reconfigurable depuis la console.

**Thème GIMAC (`themes/gimac`).** Pages de connexion, du second facteur, du mot de passe à renouveler et de la configuration du TOTP (thème `login`, dérivé de `keycloak.v2`) et courriels d'invitation, de réinitialisation et d'essai (thème `email`), en français, anglais et espagnol, aux jetons de `@gimac/theme` (bleu institutionnel, angles droits, bordures de 1 px, pied de page institutionnel). Monté dans le Compose ; intégré à l'image `Dockerfile` (`registre.gimac.local/des/keycloak:26.7.4-gimac`, avec `gimac-realm.json`) pour Kubernetes. Aperçu : `apercu-connexion.png`.

Aucun secret : mots de passe et secrets de client sont des variables `${GIMAC_...}` résolues par Keycloak à l'import, à partir du `.env` local créé par `gimac-dev.sh`. Jeton d'un utilisateur de test : `source infra/docker-compose/scripts/token.sh test-chef-ddrm` (niveau 2, par le navigateur) ou `NIVEAU=1 source ...` (niveau 1, pour vérifier les refus).
